# 백테스트 가드

경험적 패턴은 검증하기 전까지 **가설**이다. 플레이북에 규칙을 넣거나 "승률"을 말하기 전에 이 절차를 거친다.

## 1. 규칙을 먼저 고정한다
- 진입 조건, 청산 조건, 보유 한도, 성공 정의(예: "N거래일 안에 +10%")를 데이터를 보기 **전에** 적는다.
- 결과를 본 뒤 기간을 넓히거나(4~12일을 4~16일로) 임계값을 반올림(9.7%를 10%로)하지 않는다. 바꾸려면 새 가설로 등록하고 표본 밖 데이터로 다시 검증한다.
- "결국 반등했으니 성공" 같은 무기한 구출 논리는 성공으로 세지 않는다.

## 2. 데이터 위생
- 기초자산을 쓴다. 레버리지·변동성 ETP는 병합·분할과 감쇠를 조정했는지 확인한다.
- 미래 정보를 쓰지 않는다. 신호는 봉이 마감된 뒤에만 나오고, 체결은 다음 봉 시가로 한다.
- 표본은 최소 10년, 신호는 30회 이상이어야 한다. 적으면 "표본 부족"이라고 말한다.
- 기간의 앞 70%로 규칙을 만들고, 뒤 30%로 검증한다.

## 3. 보고 형식
| 항목 | 값 |
|---|---|
| 신호 횟수 | |
| 성공률 (정의 명시) | |
| 평균 / 중앙값 수익 | |
| 최대 역행폭 (MAE) | |
| 최악 사례 | |
| 단순 보유 대비 | |
| 표본 밖 결과 | |

성공률만 말하지 않는다. 최악 사례와 최대 역행폭을 항상 같이 말한다.

## 4. 도구
`src/minerva/strategy/indicators.py`의 `tm_states`, `resample`, `ma_snapshot`을 쓴다. 새 백테스트 코드는 `src/minerva/strategy/`에 두고, 고정된 합성 데이터로 테스트를 같이 쓴다(`tests/`, 네트워크 금지).
