# Minerva 🦉

바이낸스 선물 자동매매 봇과, 그 판단 근거를 보여주는 웹 화면입니다.
바이낸스 USDⓈ-M 선물을 15분봉 SCR 신호로 롱·숏 갈아타며 자동매매합니다(2026-11-08 23:00 KST BTCUSDT로 실전 시작, 2026-11-12부터 거래량 상위 50 + AAPL 중 백테스트 승률 45% 이상이고 최근 6개월 수익이 플러스인 종목).
국내 주식 자동매매(한국투자증권)는 2026-11-04부터 멈춰 있고, 분석과 알림만 계속 돕니다.
Claude(미네르바)와 서브에이전트들이 일하는 모습은 🏢 오피스 탭에서 실시간으로 볼 수 있습니다.

- 사이트: https://minerva-ai.duckdns.org/
- 언어·도구: Python 3.9+, FastAPI, systemd 타이머, 텔레그램 알림

> ⚠️ 개인 투자용 프로젝트입니다. 백테스트 수익은 미래 수익을 보장하지 않습니다.
> 이 전략은 BTC 기준 최근 1년 백테스트에서만 플러스였고 2020~2024년은 크게 마이너스였습니다. 2026-11-13부터는 최근 6개월 백테스트 수익이 플러스인 종목만 진입합니다. 자동 정지 규칙을 꼭 켜 두세요.

## 선물 자동매매

- **시장**: 바이낸스 USDⓈ-M 선물(코인과 TradFi 주식·원자재 무기한), 단방향 모드, 교차 마진, 레버리지 3배. 포지션은 한 번에 하나, 계좌 전체로 들어갑니다.
- **종목 범위**: 매주 월요일 06:05에 24시간 거래대금 상위 50개 무기한 선물을 고르고, 종목마다 같은 규칙으로 최근 6개월(182일, 상장이 늦으면 상장 이후, 2026-11-13 전엔 1년) 15분봉 백테스트를 돌립니다(`btc_universe.py` → `~/.minerva/btc_trade/universe.json`). 상위 50 밖이어도 `EXTRA_SYMBOLS`(지금은 AAPL)는 늘 넣습니다. 파일이 14일 넘게 갱신되지 않으면 처음 네 종목(BTC·ETH·SOXL·NVDA)으로 돌아갑니다.
- **관심 종목**: 바이낸스 화면 종목 줄에 `WATCH_SYMBOLS`(지금 ANTHROPICUSDT, 사용자 2026-11-13 "매매를 하던 안하던")를 늘 보여 줍니다. 보기만 하고 엔진 진입 대상이 아닙니다.
- **진입 허용**: 백테스트 승률 45% 이상, 6개월 수익 플러스, 표본이 충분한(거래 20회·60일 이상) 종목만 새로 들어갑니다. 나머지는 신호를 화면과 기록에만 남깁니다. 2026-11-13 기준(6개월) BNB 67%·+390% · TSLA 62%·+85% · XAG 61%·+238% · BTC 60%·+74% · AAPL 58%·+13% · SPY 55%·+24% · BZ 54%·+67%. 보유 종목이 진입 불가가 되면 반대 신호에 청산만 합니다.
- **신호가 겹칠 때**: 빈손에 신호가 둘 이상이거나 보유 중 다른 종목 신호가 나면 Claude(`btc_ai.choose`)가 고릅니다. 답이 없으면 승률 높은 종목이 먼저입니다.
- **신호 (SCR ①)**: 15분봉 마감 봉만 씁니다. Stochastic fast 9(20/80)·CCI 20(±100)·RSI 21(30/70)가 최근 3봉 안에 모두 기준선을 다시 넘어오면 신호입니다. 과매도에서 위로 넘으면 롱, 과매수에서 아래로 넘으면 숏입니다. 실험실과 같은 코드(`strategy/scr_lab.py`)로 계산합니다.
- **매매**: 반대 신호가 오면 청산하고 반대로 진입합니다. 같은 방향 신호면 유지합니다. 손절·익절로 청산되면 다음 신호까지 쉽니다.
- **크기**: 가용 잔고 × 97% × 3배(3%는 수수료·체결 미끄러짐·지정가와 마크 가격 차이 여유). 수익과 손실이 다음 진입 크기에 그대로 반영됩니다(복리).
- **주문 방식**: 2026-11-13부터 모든 매매를 지정가로 합니다(사용자 "시장가 말고 그 시점에 가장 가까운 지정가로 해. 거래될때까지", "모든 매매는 지정가로 해"). 청산·손절·익절은 시장가를 쓰지 않습니다(진입만 예외, 아래).
- **진입 주문**: 최우선 호가에 메이커 지정가를 걸고 최대 6회·70초 동안 한 틱씩 다시 걸어 봅니다. 급변동(1분 0.3%↑, 이번 봉 폭 ≥ ATR, 신호 뒤 0.5%↑)이거나 그래도 남으면 바로 체결되는 가장 가까운 가격(롱 = 매도 1호가)에 지정가를 걸고 5초마다 다시 겁니다(최대 60초). 60초 쫓아도 남으면 남은 수량은 시장가로 삽니다(사용자 2026-11-13 "60초 따라가다가 안되면 시장가로 하자", 추격 한도 안일 때만). 추격 한도를 벗어나면 체결된 만큼만 갖고(그 수량에 손절), 하나도 안 되면 진입하지 않습니다.
- **청산 주문**: 반대 신호·손절 실패·이미 지난 손절가·익절가는 지금 바로 체결되는 호가(매도 = 매수 1호가)에 reduceOnly 지정가를 걸고 5초마다 다시 겁니다. 이번 실행 안에 다 안 되면 지정가를 걸어 둔 채 다음 실행(15분 뒤)이 이어서 쫓습니다. 걸린 익절은 진입가보다 나쁜 가격으로는 닫지 않고, 손절·반대 신호로 평소처럼 관리하며 익절을 다시 겁니다.
- **추격 한도**: 신호 봉 종가에서 진입 방향으로 1%(15분·4시간·일봉 방향이 같으면 3%) 이상 벌어지면 진입하지 않습니다.
- **진입 실패 백오프**: 거래소가 주문을 분명히 거부한 경우(증거금 부족 -2019, 과부하 -1008)만, 남은 주문 취소·포지션 0·체결 0을 확인하고 2·5·10초 쉬었다가 새 주문 ID로 다시 냅니다. 증거금 부족이면 수량을 5%씩 줄이고, 쉬는 사이 추격 한도를 벗어나면 그만둡니다. 응답을 잃은 통신 오류는 이미 체결됐을 수 있어 다시 내지 않고 다음 실행의 대사에 맡깁니다.
- **TradFi 종목**: 휴장 중에는 진입하지 않습니다. 보유 중 휴장하면 거래소 손절이 작동하지 않아, 장이 다시 열릴 때 가격이 벌어져 있으면 3%보다 더 잃을 수 있습니다. TradFi 약관 미동의(-4411)로 거부되면 24시간 쉬고 한 번 알립니다.
- **손절·익절**: 진입가에서 3% 손절, +3% 익절(3배라 증거금 약 ±9%, 2026-11-13 사용자 결정, 그 전 +10%). 둘 다 거래소 조건부 지정가 주문(마크 가격 기준, 포지션 수량)입니다: 손절은 손절가에 걸리면 손절가에서 0.5% 안의 지정가, 익절은 익절가 지정가. **손절가에서 0.5%보다 크게 갭이 나면 손절 지정가가 체결되지 않을 수 있습니다.** 그때는 다음 실행(최대 15분)이 호가를 쫓아 닫으므로 그 사이 손실이 3%보다 커질 수 있습니다. 익절 값을 바꾸면 들고 있는 포지션도 다음 실행에서 새 값으로 다시 걸고, 이미 지났으면 지정가로 익절합니다. 백테스트(지금 매매 7종목): 최근 6개월은 익절 10%보다 수익이 크게 줄고(중간값 +69% → +21%), 1년은 비슷합니다. 2026-11-12까지는 Claude가 손절 1~5%·익절 1~10%를 골랐지만, 10종목 1년 백테스트에서 AI가 고른 것과 같은 손절 1%·익절 1%는 10종목 모두 손실이었고 3% 고정은 승률 53%여서 고정 규칙으로 바꿨습니다(`AI_EXITS = False`).
- **자동 정지** (신규 진입만 멈추고, 보유 포지션·손절은 계속 관리):
  - 평가액이 시드의 80% 아래
  - 최근 30일 승률 50% 미만(8회 이상)
  - `HALT` 파일
- **수동 매매**: 앱에서 직접 사거나 정리해도 됩니다. 15분마다 계좌 전체를 확인해, 손으로 연 포지션은 거래소 평균가 기준 손절 3%·익절 +3%를 걸고 이어받아 관리합니다(이미 손절가를 지났으면 바로 지정가로 닫습니다). 엔진이 다른 종목을 들고 있으면 그 포지션은 손절·익절 주문만 걸어 지킵니다. 수량을 바꾸면 새 평균가로 다시 걸고, 손으로 닫으면 기록만 합니다.
- **알림**: 진입·청산·손절·재시도·오류마다 텔레그램을 보냅니다. 매일 08:30 아침 브리핑에는 포지션, 밤사이 청산, 시드 대비 수익, 정지 조건까지 거리가 들어갑니다.
- **연구 기록**: 이 설정은 7만여 개 변형을 검증한 끝에 사용자가 고른 것입니다. 사전 등록 기준을 통과한 규칙은 없었습니다. 검증 과정은 연구 브랜치 `feat/btc-scr-ma`의 `docs/backtests/2026-11-0*-btc-*.md`에 있습니다.

## 국내 주식 (매매 중지)

2026-11-04부터 `HALT` 상태이고, 국내 계좌는 2026-11-06에 출금했습니다. 분석(09:10·16:30)과 운용 알림은 계속 돌고, 화면도 그대로 둡니다. 재개하면 아래 규칙으로 다시 매매합니다.

- **대상**: 코스피 시총 상위 100(보통주)과 KODEX 200. 숏·인버스·레버리지 상품은 다루지 않습니다.
- **진입 규칙**: 삼중 모멘텀 눌림(TM) 규칙 하나만 씁니다.
- **매수 관문**: 롱 매수 관문은 VIX 주봉 5주선이 10주선 아래일 때만 열립니다. 코스피 월봉이 3단을 이탈하면 신규 매수를 막습니다.
- **종목 검증**: 종목별 백테스트를 합니다. 거래 30회 이상, 표본 안·밖 비용 후 우위가 있어야 하고, 무작위 대비 p값에 BH(q=0.20)를 겁니다.
- **비중**: 개별주 30%, 지수 ETF 60%에 레짐 계수를 곱합니다. 최대 10종목입니다.
- **주문**: 매수는 전일 종가 +3% 지정가, 매도·손절은 시장가입니다. 남는 현금은 CD금리 ETF에 둡니다.
- **안전장치**: `HALT`로 멈춥니다. 봇 손익이 고점 대비 평가액의 15%를 넘게 잃으면 신규 매수를 멈춥니다.

자세한 규칙은 [`CLAUDE.md`](CLAUDE.md)와 [`.claude/skills/`](.claude/skills/)의 플레이북에, 검증 기록은 [`docs/backtests/`](docs/backtests/)에, 다음 할 일은 [`docs/ROADMAP.md`](docs/ROADMAP.md)에 있습니다.

## 설치와 실행

```bash
python3 -m venv .venv && .venv/bin/pip install -e ".[dev]"
.venv/bin/pytest                                   # 테스트
.venv/bin/ruff check . && .venv/bin/ruff format .  # 린트·포맷
```

서버와 타이머는 `deploy/`의 systemd 파일로 설치합니다. 각 파일 맨 위 주석에 설치 명령이 있습니다.

비밀값은 저장소 밖에 둡니다. 절대 커밋하지 않습니다.

| 파일 | 내용 |
|---|---|
| `~/.minerva/binance.env` | 바이낸스 API 키 (선물 거래만, 출금 권한 없음, IP 제한) |
| `~/.minerva/kis.env` | 한국투자증권 앱 키·계좌 |
| `~/.minerva/telegram.env` | 텔레그램 봇 토큰 |
| `~/.minerva/tls/` | HTTPS 인증서 |

### 선물 자동매매 운용

엔진 상태 파일은 `~/.minerva/btc_trade/`에 있습니다(`mode`, `state.json`, `orders.jsonl`, `closed.jsonl`, `events.jsonl`).

```bash
python -m minerva.btc_trade preflight            # 사전 점검 (조회만)
python -m minerva.btc_trade start-live --confirm # 실전 시작: 그 시각 잔고를 시드로 (사용자 확인 후에만)
touch ~/.minerva/btc_trade/HALT                  # 신규 진입 멈춤 (텔레그램 "매매중지")
echo dry > ~/.minerva/btc_trade/mode             # 주문 끄기 (거래소에 걸린 손절·익절은 남음)
python -m minerva.btc_universe show              # 종목 범위와 종목별 백테스트 승률
python -m minerva.btc_universe refresh           # 종목 범위 다시 만들기 (공개 시세, 15~25분)
```

### 국내 주식

국내 실주문은 `~/.minerva/trade/mode`가 `live`이고 `HALT`가 없을 때만 나갑니다.

```bash
python -m minerva.strategy.report 005930.KS ^KS11            # 지표 값
python -m minerva.strategy.backtest --help                   # 규칙 백테스트
python -m minerva.strategy.portfolio --start 2021-10-29      # 포트폴리오 백테스트
python -m minerva.trade preview                              # 다음 날 주문 미리보기 (주문 안 냄)
python -m minerva.audit                                      # 운용 점검
```

## 에이전트 오피스

🏢 오피스 탭은 Claude Code가 이 저장소에서 일하는 모습을 작은 사무실로 보여줍니다.
Claude Code 훅(`scripts/office_hook.py`)이 이벤트를 `~/.minerva/office/events.jsonl`에 쌓고, 화면이 1.5초마다 `/api/office/events`를 읽어 그립니다.

### 요원

| | 이름 | 에이전트 | 맡은 일 |
|---|---|---|---|
| 🦉 | 미네르바 | Claude 본체 | 지시를 받아 일을 나누고, 요원을 투입하고, 결과를 검토해 보고합니다. 코드 작성·커밋도 직접 합니다 |
| 🦊 | 전략가 | `strategist` | 플레이북 순서로 종목을 점검해 롱·숏·관망 결론과 진입·무효화 가격을 냅니다 |
| 🐻 | 레드팀 | `red-team` | 실전 규칙·주문 코드 변경, 백테스트 결론, 매매 결론을 보고하기 전에 독립적으로 반박·검증합니다. 비중·손절 위반과 사후 맞춤도 봅니다 |
| 🐿️ | 백테스터 | `backtester` | 가설을 먼저 고정하고 과거 데이터로 규칙을 검증합니다 |
| 🦅 | 운용 감시관 | `trade-auditor` | 실계좌 주문·보유·손절이 규칙대로였는지 점검합니다. 주문은 내지 않습니다 |
| 🐧 | 리뷰어 | `reviewer` | 바뀐 코드에서 버그·보안·빠진 테스트를 찾습니다 |
| 🐕 🦝 🐱 | 탐색가·설계자·만능 요원 | `Explore`·`Plan`·`general-purpose` | 코드 탐색, 구현 계획, 여러 단계 조사 |
| 🦉 | 분신 | `fork` | 미네르바가 맥락을 그대로 가지고 나눠진 분신입니다. 큰 일을 병렬로 처리합니다 |

요원 정의는 [`.claude/agents/`](.claude/agents/)에 있습니다. 요원을 누르면 맡은 일과 최근 작업이 나옵니다.

### 요원들이 움직이는 방식

| 무슨 일이 생기면 (훅 이벤트) | 화면에서 |
|---|---|
| 세션 시작 (`SessionStart`) | 미네르바 책상에 "☀️ 출근 완료" |
| 새 지시 (`UserPromptSubmit`) | 🧑‍💼 사용자(사장님)가 사무실 가운데로 걸어와 서류를 건네고, 미네르바 말풍선에 "📄 새 지시 접수!" |
| 도구 사용 (`PreToolUse`) | 그 요원이 들썩이며 일하고(타이핑), 모니터가 깜빡이고, 말풍선에 도구 아이콘과 작업 이름이 뜹니다. 예: ⌨️ 테스트 실행, ✏️ trade.py, 🔍 검색 |
| 요원 투입 (`Agent` 호출 → `SubagentStart`) | "○○ 투입!" 알림과 함께 새 책상이 왼쪽에서 미끄러져 들어오고 "🚶 출근 중" → "💼 업무 시작" |
| 실패 (`PostToolUseFailure`) | 모니터가 빨갛게 바뀌고 "❌ ○○ 실패" |
| 커밋·푸시 | "🎉 커밋·푸시!" 알림, 커밋 수 증가 |
| 확인 요청 (`Notification`) | "✋ 확인이 필요해요!" |
| 요원 업무 종료 (`SubagentStop`) | 잠시 뒤 책상이 오른쪽으로 빠져나가며 퇴근 |
| 작업 끝 (`Stop`) | 미네르바가 "💤 대기 중… 다음 지시 기다리는 중" |
| 45초 동안 이벤트 없음 | "☕ 잠깐 쉬는 중" |
| 19시~07시 | 사무실 조명이 어두워지는 야간 모드 |

화면에는 도구 호출·투입 에이전트·커밋·푸시 횟수와 실시간 연결 표시가 있고, 📜 작업 로그에 최근 작업이 흐릅니다.

### 기록하는 것과 안 하는 것

이벤트 종류, 도구 이름, 짧은 라벨(Bash 작업 설명, 파일 이름)만 기록합니다.
프롬프트 본문, 명령 원문, 파일 내용, 메시지 본문은 기록하지 않습니다.
훅은 어떤 경우에도 정상 종료해서 Claude 작업을 막지 않습니다.

### 설치

```bash
python3 scripts/install_office_hooks.py   # ~/.claude/settings.json 에 훅 등록
```

사용자 호칭(기본 "사장님")은 서버의 `~/.minerva/profile.json`(`{"boss": "이름"}`)에서 바꿉니다. 실명이 저장소에 들어가지 않게 파일로 둡니다.

기본은 토큰 없이 공개입니다. 잠그려면 웹 서비스에 `MINERVA_OFFICE_TOKEN` 환경변수를 설정하고 `?token=...`으로 한 번 접속합니다. 토큰은 그 기기에 저장되고 주소창에서는 지워집니다.
